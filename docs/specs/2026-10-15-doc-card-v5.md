# Doc card v5: the documentation pilot layout

Status: planned
Reviewed: 2026-10-26 — plan ready to build (second plan pass; its one gap and minor notes since applied)
Date: 2026-10-15

## Goal

ThroughLine's Figma doc card today is a component set with a hand-made header and
one scripted band (Usage, `scripts/lib/doc-card-render.figma.js`, renderer `'4'`).
Manyfest's "Documentation Pilot" artboard (file `0AgaYH2xuGNKKDW1pRYLkg`, page
"🗄️ Documentation template", artboard `23546:2623`) shows a better shape: a dark
header, then stacked white bands for specimen, variants, properties, usage,
accessibility and tokens, with live instances and token swatches in them.

After this ships, every documented component gets a card in that shape, rendered
from its record plus what Figma already knows (its properties, variants and
variables). The card works for any design system and uses no particular brand.
The chrome (header, band titles, chips) comes from two kit components the
designer can restyle.

## Non-goals

- Anatomy, Content, Platform differences, Related, and live Do/Don't examples.
  Each becomes its own issue (decision 22).
- A separate docs page. Cards stay where they are (decision 6).
- A separate light/dark kit preview (decision 13).
- Figma slots. No band uses one (decision 14).
- Copying Manyfest's brand, fonts, colours or `_Doc/Band` slot structure.
- Changing the record schema. The record stays prose and the structural facts are
  read from Figma (decision 3).

## Plan

Release Step 1 only (decision 22): schema 8, the kit, the header, the Specimen
band, tagging and lookup by name, the v4 migration, and the Usage band. Steps 2
and 3 each get their own Plan section and live run. Plan steps are numbered 1.x
so they don't collide with the release steps.

Names this plan fixes, which decision 21 and audit item 4 then enforce:

- `_Doc/Header` is a component set of four components named `Status=draft`,
  `Status=beta`, `Status=stable`, `Status=deprecated` (so its variant property
  is `Status`), with text properties `Title`, `Summary`, `Updated`.
- `_Doc/Band header` is a component with text properties `Title`, `Lede` and
  boolean property `Unreviewed`.
- Band frames are named `Band: <Title>` (`Band: Specimen`, `Band: Usage`).
- Shared plugin data, all in namespace `throughline`: `docCard` = component
  name (card frame), `docKit` = `header` | `bandHeader` (the header's component
  set, and the band header component), `docKitFile` = file key (`figma.root`).
- A kit property is matched by name: the part of a `componentPropertyDefinitions`
  key before `#` (variant keys have no `#`). Zero or several matches throws,
  naming the property (decision 21).

### Step 1.3 — Renderer v5 (Figma)

Files: `scripts/lib/doc-card-render.figma.js`
Change: Replace `renderDocCard` with `renderDocCard({ componentName, nodeId,
record, vars, textStyles, fileKey, docKitFileKey, status })` and add
`setDocCardStatus({ componentName, status })`. `fileKey` is the manifest's
`figma.fileKey`; `docKitFileKey` is `figma.docKit.fileKey` or `null` when the
kit isn't recorded. In this order, with every check before any mutation:

1. **Card.** `await figma.loadAllPagesAsync()`, then
   `figma.root.findAllWithCriteria({ sharedPluginData: { namespace:
   'throughline', keys: ['docCard'] } })` filtered to value `componentName`.
   More than one: throw naming both ids. None: with `nodeId`, get that node; it
   must be a VERTICAL auto-layout frame. Without `nodeId`: throw asking for
   `--node-id`. Either way, the card must hold exactly one `COMPONENT_SET`,
   named `componentName`; more than one set, or a band named `Usage — …`,
   throws today's split-the-card message (decision 19).
2. **Shape.** Classify the card's direct children. Resolve instances with
   `await instance.getMainComponentAsync()` (`.mainComponent` throws in
   dynamic-page mode). Allowed: the header instance (its main component's
   parent set carries `docKit = header`), `Band: *` frames, the child holding
   the specimen (or the set itself), a legacy `Usage` frame, and a legacy
   header (one other child frame, found structurally as today), plus a hidden
   `Doc Fingerprint` text. Anything else throws, naming it.
3. **Kit, found.** Find the kit by the `docKit` tag. If `docKitFileKey` is set:
   both kit components must exist, and `figma.root`'s `docKitFile` must equal
   `docKitFileKey`, otherwise throw (a different file names `docKitFileKey` and
   the root's key; a missing kit says to set `figma.docKit` to `null`). Every
   property name in "Names this plan fixes" must match exactly once.
4. **Status.** If there is no header instance, `statusVariant(status)` (throws
   on a missing or unknown value).
5. **Plan.** `const plan = planDocCard(record)`.
6. **Kit, drawn** (only when `docKitFileKey` is `null`). On a `Documentation
   Kit` page (created if absent):
   - `_Doc/Header`: four components, each a VERTICAL frame filled
     `surfaceHeader`, padding `spacePadding`, item spacing `spaceItemGap`.
     Inside: a title row (HORIZONTAL) holding the title TEXT (`title` style,
     `textOnHeader`) and the status chip (a frame with no fill, a 1px stroke,
     radius `radiusBand`, holding a label TEXT in the `caption` style; stroke
     and label bound to `textOnHeader`, decision 27 as amended), then the summary TEXT
     (`body`, `textOnHeader`) and the date TEXT (`caption`, `textOnHeader`).
     Combine them with `figma.combineAsVariants`, name the set `_Doc/Header`,
     then `addComponentProperty('Title' | 'Summary' | 'Updated', 'TEXT', …)`
     on the set and point each text node's
     `componentPropertyReferences.characters` at the returned key in every
     variant.
   - `_Doc/Band header`: a VERTICAL component, item spacing `spaceItemGap`,
     no fill, holding a title row (title TEXT in `bandTitle`, `textDefault`; the
     Unreviewed chip drawn as above in `toneCaution`, labelled `Unreviewed`)
     and the lede TEXT (`body`, `textMuted`). Add `Title` and `Lede` (TEXT) and
     `Unreviewed` (BOOLEAN, default false); point the chip's
     `componentPropertyReferences.visible` at `Unreviewed`.
