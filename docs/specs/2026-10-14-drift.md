# Drift

Status: built
Reviewed: 2026-10-14 — needs revision (second pass; all findings applied)
Date: 2026-10-14
Issues: #44 (drift for composed screens), #46 (ongoing drift between Figma and code)

## Goal

Today nothing notices when the system moves under the things built from it. A
screen composed last month can name a variant that no longer exists, a token sync
can be weeks behind Figma, and a hand edit to generated token output survives until
the next sync silently wipes it. After this ships, `/throughline:drift` reports all
three, and the code half runs as a plain script (`drift:check`, installed with the
documentation scripts) a consumer can put in CI:

- **Screens.** Every composed screen, code or Figma, is recorded with what it used
  and a fingerprint of each component's contract at the time. A screen is
  **broken** when something it uses is gone, **stale** when a component's
  contract (its variants, states or tokens) changed since, and **clean** otherwise.
- **Token output.** Generated token files are stamped when they're synced. A file
  that no longer matches its stamp was **edited** by hand.
- **Figma variables.** With the bridge open, the live variables are compared to a
  stamp taken at the last sync. A difference means the sync is **overdue**, with
  the collections that moved (see Where it diverged).

## Non-goals

- **Component drift between Figma and code.** #46's second case, "a Figma
  component changed and its code counterpart did not", needs a link between a
  Figma component set and a code component beyond the name, and a reader for code
  props across frameworks. Neither exists. It gets its own issue.
- **A second fingerprinting scheme.** Stale compares a narrower projection of the
  same doc record with the same hash (`scripts/lib/doc-record.mjs`), not a new
  hash over source or Figma structure.
- **Token value changes on a screen.** A screen binds tokens by name, so a new
  value flows through on its own. That's tokens working, not drift. Only a token
  that's gone counts, and the existing gates already catch that.
- **The Figma half of `docs:check`.** The doc card's `Doc Fingerprint` node says a
  Figma-side pass reads it, and none does. Real gap, separate issue.
- **Fixing drift.** The report says what moved and which command fixes it
  (`/throughline:sync-figma-tokens`, a re-compose, `/document-component`). It
  doesn't rewrite screens or re-sync.
- **Screens nobody composed.** Only screens throughline composed and recorded are
  tracked. A hand-made screen has no record to drift from.

## Open questions

- **Should `/throughline:sync-figma-tokens` refuse to overwrite edited output?**

  since the output is a build artifact by definition. Unresolved, small. The plan
  has it warn.
- **Do old screens get backfilled?** Screens composed before this ship have no
  record. Recommendation: no backfill. They show up once recomposed. Unresolved.

## Where it diverged

- **The Figma variable stamp holds one fingerprint per collection, not every
  value.** The Decisions row chose values compared in Node so the report could
  say `16 → 20`. In the live run an agent couldn't carry 147 values through a
  36 KB snippet into a file, and a real system has many more. The snippet now
  hashes each collection in the sandbox (FNV-1a, as `doc-card-render.figma.js`
  does) and the report names the collections that moved; the sync's diff names
  the variables. `compareVariables` became `compareCollections`.
- **`figma-drift.md` has two snippets, not one**, so the variables stamp every
  sync takes is 5 KB rather than 36 KB. The reader is two files, not
  `figma-drift.figma.js`, with entry points `runDriftVariables()` and
  `runDriftScreens(SPEC)` instead of `runDrift(MODE, SPEC)`.
- **The description walk.** Step 2 described `frame.children[]` and
  `component.slots`. The real shape is flatter: a frame node holds `children`, a
  component node holds `component` (a name) and `slots`, and the walk starts at
  `root`.
- **`compare-figma` exits 1 when a collection moved**, to match `check`; the plan
  had it print only.
- **`check` lists the options a broken variant has now**, from the error
  `checkPlan` already returns. Found in the live run.
- **Existence comes from `components.built` as well as `components.meta`.** The
  plan looked components up in `meta` only, which is added lazily as docs are
  written, so a built but undocumented component was dropped from the record and a
  removed `meta` entry read as "no longer in the system". A component that's gone
  is now the plan check's finding (code) or the live pass's (Figma), never a
  repo-side "broken" for a Figma screen. Found in the whole-branch review.
- **`record` refuses a `--screen` or `--target` that differs from the plan.** A
  screen recorded under another name than its marker would read as released on
  every check and hide what broke later. Found in the whole-branch review.
- **`drift:check` is registered with `--allow-empty`.** The Decisions row has an
  empty run fail CI, but every upgraded repo is empty until its next sync, so the
  install-set registration allows it, still printing "nothing checked". `check`
  itself keeps the stricter default.
- **The live run was partial**, as its note says: the sync and the composers'
  record steps were run by hand rather than by a full command run.

### Step 3 — the code-side check and the token stamp

Files: `scripts/drift-check.mjs`, `scripts/drift-check.test.mjs`
Change: Header, pure functions, thin `main`, as Step 2.
- `check --system <dir> [--json] [--allow-empty]`. Screens: for each code entry,
  target gone → broken; `readMarker` of the file is not this screen → released;
  else `checkPlan(plan, codeInventory({ manifest, index }))` errors → broken with
  their messages (`index` read only when a code entry exists). For every entry,
  each recorded key whose `contractOf` fingerprint now differs → stale, naming it;
  recorded `null` → untracked. Figma entries are listed as "checked live only"
  beyond that.
- `stamp --system <dir> --out <dir> [--out <dir>...]`: `--out` resolves against
  the working directory and is stored relative to `--system`. Writes
  `design-system/token-stamp.json` `{ roots, files: { <path relative to system>: sha256 of LF-normalised text }, at }`,
  keeping any `figma` key. Tokens in `check`: walk the recorded roots → edited,
  missing, unstamped.
- `stamp-figma --system <dir> --from <live.json>` writes the live variable map
  under `figma`. `compare-figma --system <dir> --from <live.json> [--json]` diffs
  stored against live with sorted keys into `{ added, changed: [{ name, from, to }], removed }`
  (no stamp → "no Figma stamp yet", exit 0). Both pure parts exported for tests.
- Output: one section per half, then counts. Nothing recorded and no stamp →
  "nothing checked", exit 1 unless `--allow-empty`. Otherwise exit 1 on broken,
  edited or missing; else 0; 2 usage. `--json` prints `{ screens, tokens, counts }`.
Verify: `node --test scripts/drift-check.test.mjs` → clean, clean with a sub-part
in the plan, stale (variant added), not stale (summary reworded), broken
(component gone, variant gone, file gone), released (no marker, other screen's
marker), untracked; a stamp, then an edit, a delete, an add → three findings; a
CRLF-only change → no finding; a file outside the roots (a `build.mjs` beside
them) → no finding; no index on disk and no code screens → runs; nothing
recorded → exit 1, and 0 with `--allow-empty`; compare-figma: a changed value
named with from/to, mode order swapped → no change; exit codes 0/1/2.
