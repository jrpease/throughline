# v0.16.0 shipped — handoff

**Date:** 2026-08-28
**Supersedes:** `2026-08-27-stacked-native-prs-handoff.md`, which still describes
PR #76 as open and ten changelog entries as unreleased. Both were true when
written and are not now.

## State in one line

`main` is at `36c3359`, clean, **0 open PRs**, 403 tests, six gates green.
`@radicool/throughline@0.16.0` is published to npm with provenance and tagged
`v0.16.0`.

## What shipped in 0.16.0

Ten changelog entries across nine issues — #34, #50, #51, #52, #53, #54, #55,
#60, #64, #70 — all in the native token adapter, all the same shape of defect:
output that looked right and was not. Android text ignoring the user's font-size
setting, ratios emitted as pixel measurements, tokens dropped silently on a name
collision, and two gates passing exactly what they existed to catch.

**It is a breaking release**, and the changelog now has a `Breaking` section
saying so — the file had never had one, and every build-breaking change was
filed under `Fixed`, which nobody reads as "your app will stop compiling."

Native token coverage against zygarden's real source:

| | before 0.16.0 | now |
|---|---|---|
| Kotlin declarations | 195 | **208** |
| Swift declarations | 195 | 195 |
| unmatched source tokens, Android | 19 | **6** |
| unmatched source tokens, iOS | 19 | 19 (by decision) |

**Android's remaining 6 are 4 fixable + 2 unrepresentable.** The four are
`typography.letterSpacing.{tight,normal,wide,widest}`, whose leaf names state no
role — tracked on #63, which now carries that evidence. The other two are a
`linear-gradient()` and a `100%`, which have no native form at all. So closing
#63 would take Android to 2 unmatched, both genuinely impossible.

**iOS letter spacing is excluded deliberately, not pending.** It is an
`NSAttributedString` kern in points, needing a font size the token does not
carry, so no constant Swift could emit is right at every font size.

## The thing most worth knowing next session

**Both native compilers are available, and every e2e note says they are not.**

- `swiftc` was at `/usr/bin/swiftc` the whole time via Xcode CLT. Nobody checked.
- `kotlinc` 2.4.10 was installed 2026-08-27 (`brew install kotlin`, pulls openjdk).

Kotlin typechecks to real bytecode against ~10 lines of Compose stubs; Swift can
only `-parse`, because `UIKit` is unavailable on the macOS command line. Compiling
caught three things reading did not, two of which contradicted a written claim —
including one that would have shipped #64 broken. Tracked as **#81**, with the
stub source in the issue body.

## Where the backlog stands

Nothing is blocked. The genuinely open question is which slot is next:

- **#63** — the cheapest meaningful win, and now the *only* fixable native token
  gap. Takes Android from 6 unmatched to 2.
- **#80** — `release.yml` runs five of CI's six gates, missing the
  native-adapter-config doc check, and `references/` ships in the tarball. Four
  lines, plus the better question of why two hand-maintained gate lists exist.
- **#81 / #77** — make e2e runs prove more: compile the output, and require a
  discriminating fixture when the PASS condition is an absence.
- **#36** — validator silently drops a token on a `normalizeKey` collision. Last
  of the "instruments" items, outside the contended `sd-native.mjs`.
- **Native tail** — #57, #58, #61, #62, #67, #71, #72, #75. #71/#72 are one
  underlying gap in the advisory's type resolution and should be done together.
- **Consumption layer** — #39–#44, parked pending a clean native base, which it
  now has. This is the largest unstarted body of work that is *not* #48.
- **#48** — native SwiftUI/Compose **components**. Multi-month, not a gap. Worth
  keeping distinct from token work in any roadmap statement; the two were
  conflated in a README bullet until #34 split them.

## Open questions, honestly stated

- **Is a release cadence wanted?** 0.16.0 followed 0.15.0 by two weeks with ten
  entries batched. That worked, but it meant breaking changes sat unreleased for
  a while.
- **Should compile verification be a CI gate or stay an e2e-time step?** It needs
  a JDK on the runner and stubs to maintain. #81 asks for an explicit decision
  rather than drift.
- **Two hand-maintained gate lists have now silently diverged once** (#80). Fixing
  the symptom leaves the mechanism.
