# Adherence gate — end-to-end run (#39)

Date: 2026-08-31
Subject: `scripts/validate-adherence.mjs`, Task 6 of
`docs/superpowers/plans/2026-08-31-code-adherence-gate.md`

Every gate in this project verified only at the unit layer has been wrong about
what it emits. Fixtures prove the rules; only a real repo proves the extraction.
This is that run.

## What the plan assumed, and what is actually on disk

The plan said: run against `~/Dev/throughline-sample`, an app consuming a built
system. **There is no such app.** `apps/` in that repo contains one file,
`.gitkeep`. The only file importing `@ds/ui` is the UI package's own barrel,
`packages/ui/src/index.ts`; the stories import relatively (`./Button`), which no
package-specifier scan will ever see.

A survey of the other systems on this machine found the two halves split across
two repos and never together:

| Repo | Manifest | Docs index | Consuming app |
| --- | --- | --- | --- |
| `throughline-sample` | yes, 14 built | yes, all 14 documented | **no** — empty `apps/` |
| `throughline-ds` | yes, 8 built | **no** — `docs:digest` never run | yes, a real Next.js site |
| `zygarden-frontend` | yes | no | yes (Angular/SCSS, no JSX) |
| `sweet-ds` | no | no | — |

So the harness below takes the **system side entirely from real records** —
`throughline-sample`'s `design-system.json`, its `design-system/docs/index.json`
as generated by `docs:digest`, and its three real DTCG token files — and pairs
them with a **consuming app written for this run**, because none exists. That
is a real limit on this evidence and it is stated here rather than buried: the
rules and the report are proven against real vocabulary, and the extraction is
proven against real-shaped TSX, but no run in this note reads app code that a
person wrote for their own purposes.

## The bug this run found

The very first invocation, against the real (empty) `apps/`:

```
tokens:validate-adherence — 0 usages, 0 colour literals, 0 files
  components:   0 referenced, 0 undocumented
  variant axes: 0 of 0 literal attributes matched a declared axis
  not read:     0 of 0 attributes are expressions, not literals
exit=0
```

**A clean pass having read nothing.** Decision 7 makes each rule fail when its
own inputs are missing, and each rule was individually satisfied: the token map
loaded 112 paths, so `colour-rule-inert` stayed quiet; no component was
referenced, so `variant-rule-inert`'s `knownComponents.size > 0` guard stayed
quiet. Nothing asked whether the *scan* had found anything.

This is the exact failure class the gate was written to prevent, occurring in the
gate. Every unit test passed throughout — the fixtures all supply files, so none
of them could reach this state.

Fixed by a `nothing-scanned` rule: `usages === 0 && literals === 0` fails, and
names the two things that actually cause it (a wrong `--root`, or a `--package`
specifier the app does not import under — the second being precisely what the
sample repo's relative imports would produce). Re-run:

```
1 rule failure(s):
  - [nothing-scanned] 0 file(s) yielded no component reference and no colour
    literal, so this run verified nothing. Check --root points at the consuming
    app, and that --package is the specifier that app actually imports from.
exit=1
```

Three tests now pin it, including one asserting the rule goes quiet as soon as a
single literal is read.

## Clean run

Harness: the authored app (2 files, 8 components referenced) against
`throughline-sample`'s real records.

```
node scripts/validate-adherence.mjs --root <app> --system ~/Dev/throughline-sample \
  --package @ds/ui \
  --tokens .../dtcg/primitives.json \
  --tokens .../dtcg/semantic.light.json \
  --tokens .../dtcg/semantic.dark.json
```

Package specifier `@ds/ui` read from `packages/ui/package.json`, not guessed.

```
tokens:validate-adherence — 19 usages, 0 colour literals, 2 files
  components:   8 referenced, 0 undocumented
  variant axes: 13 of 15 literal attributes matched a declared axis
  not read:     4 of 19 attributes are expressions, not literals

6 advisory note(s) — reported, not gating:
  - [dynamic-value] Avatar alt={…} at components/dashboard.tsx:9
  - [dynamic-value] Input size={…} at components/dashboard.tsx:11
  - [unmodelled-prop] Input "placeholder" at components/dashboard.tsx:11 — …the
    system models this component's axes as size
  - [dynamic-value] Select Menu onChange={…} at components/dashboard.tsx:12
  - [unmodelled-prop] Select Menu Item "value" at components/dashboard.tsx:13 — …
    axes as selected, disabled
  - [dynamic-value] Button onClick={…} at components/dashboard.tsx:15
exit=0
```

**`<SelectMenu>` did not report as `unknown-component`**, and neither did
`<SelectMenuItem>`. This is the measured bug from
`2026-08-31-adherence-convention-measurement.md`: `components.built` holds the
display names `"Select Menu"` and `"Select Menu Item"` while the code exports
`SelectMenu` / `SelectMenuItem`. Without `normalizeName` this gate would have
failed correct code, on day one, in the only complete sample system that exists.
Both appear in the advisories under their **declared** names, which is the right
way round: the report speaks the system's vocabulary.

`disabled="false"` on Button matched the declared *state* `disabled` rather than
being reported as unmodelled, confirming the states fallback fires.

## Axis coverage — the number that decides whether phase 4 is needed

**13 of 15 literal attributes matched a declared axis (87%).** The two misses are
both correct: `placeholder` on Input and `value` on SelectMenuItem are real React
props that are not design-system axes, and both are reported as advisories rather
than failures.

Four of 19 attributes (21%) are expressions the regex cannot read. That is the
gate's honest blind spot and it is printed in the headline on every run, not
buried in a limitations section.

This supports the measurement's prediction: in a generated system, the code's
attribute names and the records' axis names agree, so `variant-rule-inert` is not
the common case and the rule does real work. It does not extend to hand-written
brownfield systems, which no run here touched.

## Proving it can fail

A copy of the app with three injected defects. A gate that has never failed is
not a gate.

| Defect | Injected | Reported |
| --- | --- | --- |
| Undeclared variant value | `<Button variant="tertiary">` at `dashboard.tsx:19` | `[unknown-variant-value] Button variant="tertiary" at components/dashboard.tsx:19 — declared values for "variant" are default, secondary, destructive, outline, ghost, link` |
| Component not in the system | `<Nonexistent />` at `dashboard.tsx:11` | `[unknown-component] <Nonexistent> at components/dashboard.tsx:11 — not in design-system.json components.built` |
| Literal duplicating a token | `#2ACF6B` at `settings.tsx:7` | `[token-exists-for-literal] #2acf6b at components/settings.tsx:7 — color.green.400 resolves to exactly this value` |

All three named, all three at the right file and line — checked against `awk`
on the injected files, not read back off the gate's own output. `exit=1` on the
defective copy, `exit=0` on the clean one.

The colour case is the one worth noting: `#2ACF6B` was taken from the real token
source by resolving `color.green.400`, and the gate matched it case-insensitively
through `normalizeHex` and named the token path. Decision 3 held throughout —
the clean app has no colour literals at all, and no literal without a token was
ever reported in either run.

## Residual risk

- No run here reads app code written by a person for their own purposes. The
  extraction is proven against real-shaped TSX, not against a real app's TSX.
- JSX only. A Vue or Svelte consumer must `--skip` both component rules and run
  the colour rule alone; that path has unit coverage but no e2e.
- Multi-line JSX tags whose attributes span lines are attributed to the line the
  tag opens on, not the line the attribute sits on. Correct for the failures
  above; would be coarse for a heavily wrapped element.
- `variant-rule-inert` against a hand-written brownfield system is untested. The
  87% here comes from a generated system, where both sides were produced from
  one source.
