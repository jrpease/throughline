### The consumer-visible change

A dimension referenced **only** by `fontSize` / `letterSpacing` / `lineHeight`
members is now inferred typographic from the reference graph, so `text.base`
emits `sp` rather than `dp` and an `em` letter-spacing primitive reaches Compose.
**Breaking on Android**: nine Kotlin symbols change type from `Dp` to `TextUnit`,
so a use site like `Modifier.padding(Tokens.textBase)` stops compiling — which is
the point, since those symbols were always font sizes. Swift is byte-identical;
the sp/dp distinction is Compose-only. Opt out per token by stamping
`$extensions["com.radicool.throughline"].nativeUnit` to `"device"`.

Two advisories were added alongside it, both reported and never gating:
`unreferenced-text-sibling` (a primitive nothing references, so no role can be
inferred) and `ambiguous-text-role` (referenced by both kinds of member, so the
inference declines rather than guesses).

**0.17.0 rather than 1.0.0**, on 0.16.0's reasoning: the breakage is real, but
the project is pre-1.0 and the governance and consumption-layer work is unbuilt,
so a major would claim a stability commitment nobody has decided to make.
