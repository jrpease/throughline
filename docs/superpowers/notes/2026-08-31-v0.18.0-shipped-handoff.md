## What shipped in 0.18.0

One change, #85 (PR #88, `210b280`): all three text-role gates —
`classifyTextUnits`, `applyTextRoleGraph`, and `textRoleGraph`'s
`unreferencedSiblings` walk — now resolve DTCG 5.2.2 inheritance through
`flattenDtcgTypes` instead of reading each token's own literal `$type`.

**The scope claim is the part worth remembering**, because the first draft got
it wrong and a review caught it. Style Dictionary runs global preprocessors,
then its own `typeDtcgDelegate` (which *is* 5.2.2), then platform preprocessors.
`nativePlatform` registers ours at platform level, downstream of that
delegation. So:

| wiring | before | after |
|---|---|---|
| `nativePlatform` only | 208 decls / 48 `sp` | identical — **never affected** |
| + top-level `preprocessors` | 205 / 39 | 208 / 48 |

The affected wiring is the one our own usage snippet teaches, which is why the
fix was needed. But "every consumer is affected" was never true, and both the
changelog and the e2e note now say which wiring is which. **Any future claim
about this pipeline has to name the wiring** — it is the input that decides the
result, and an e2e that does not record it has held its most important variable
fixed by accident.

## Two releases in one day, on purpose

0.17.0 shipped the reference-graph inference. #85 meant that inference stamped
**nothing at all** on group-typed sources. Shipping the feature and the reason
it does not fire in a single release would have buried the second inside the
first.

## Filed rather than fixed, both deliberately

- **#89** — `hoistDualNodes`' `$type` carry runs *after* classification, so a
  child typed only by that carry is never stamped. Different mechanism from #85;
  changing it under cover of #85 is the mistake #63 avoided.
- **#90** — `preprocess` is **not idempotent** where the hoist invents a
  typographic name (`a.font` + `size` → `a.fontSize`). **Verified pre-existing**
  against `a349453` before it was attributed: 0.18.0 widens the hole, it does not
  open it. No output changes in either wiring. It matters because idempotency is
  asserted unconditionally in four comments that ship through
  `references/native-adapter-config.md`, one of which is the advice that
  double-registering the preprocessor is harmless. Pinned in both directions by
  test, so a fix has something to turn green.

## Numbers corrected this session

- **"322 tokens" was stale and had propagated for ten days.** The real source
  holds **318** `$value` entries across 15 files and **211** under the
  light+mobile pin every e2e uses. 322 belongs to
  `libs/shared/util-tokens/src/tokens/`, a path that no longer exists. Recount
  before reusing a denominator.
- **#85's own "zero `sp`" was wrong** — measured, 39. A partial no-op: the
  member-name pass survives wherever typographic members carry their own
  `$type`. The graph half was the total one.
- **No test in this repo measures emitted `sp`.** Nothing here runs Style
  Dictionary under test (`fakeStyleDictionary` is a registration spy), so the
  step from "no stamp" to "no `sp`" is only ever established by an e2e. An
  earlier draft claimed unit-test coverage it does not have.
