## What shipped, and how it was cut

**Twelve issues in one release** — #36, #57, #58, #61, #62, #67, #71, #72, #75,
#87, #89, #90 — across nine PRs, batched rather than cut as they landed.

That is the correction, and it is the most important thing in this note.
**0.16.0, 0.17.0 and 0.18.0 went out in five days over one body of work**, each
cut when a PR merged. 0.17.0 shipped the reference-graph inference and 0.18.0
shipped, four hours later, the fix that makes it fire at all. A consumer on
0.15.0 was asked to re-check their Kotlin use sites three times in a week.

The rule adopted, and to keep: **a release is a theme, not a merge.** Landing a
PR is routine; cutting a release is deliberate and needs a one-sentence story a
consumer acts on. Never split a feature from the fix that makes it work.
Breaking changes batch. Default to *not* releasing — leave it in `[Unreleased]`
and raise the release as a question with the theme named.

## The story 0.19.0 tells

The dual-node hoist repairs what it breaks by carrying a `$type` onto a hoisted
child. That repair was both too wide and invisible:

- **#67** too wide — it fired onto hoisted **groups**, typing every token beneath
  one with something the source never said.
- **#89** invisible to classification, which runs before the hoist, so a line
  height emitted `20.00.dp` instead of `sp`.
- **#71** invisible to the `unitless-dimension` advisory, which reads raw source.
- **#61** and when the hoist did complain, it named a path the author never wrote.

**`flattenPipelineTypes` is what ties them together**: DTCG 5.2.2 *plus* the
carry, computed from the raw tree ahead of time, so classification and the
advisory read one resolution instead of two that drift. Worth remembering as a
technique — **a rule that runs later can be modelled earlier, as long as its
inputs are all present earlier.** #71's issue said the only fix meant pointing
the gate at the preprocessed tree and rejected it, because the gate would stop
checking against what the author wrote. Modelling the carry rather than applying
it keeps that property. The issue's framing was a false choice.

Alongside it, the validator's own blind spots: #36, #57, #58, #62, #75.

## Traps hit this session, written down so they are not hit again

- **Stacked PRs.** `gh pr merge <parent> --squash --delete-branch` auto-closes
  every child PR, and a closed PR whose base branch is gone **cannot be reopened
  or retargeted**. #94's description was lost and had to be recreated as #96.
  Either retarget children to `main` first, or merge the parent *without*
  `--delete-branch`. Better: do not stack more than two deep here.
- **The e2e harness in `/private/tmp` gets partly cleared.** Directory tree
  survives; `build.mjs`, `tokens/` and `node_modules` do not. Check before
  believing a note that says "reused, still alive". The current harness has two
  build scripts — `build.mjs` (top-level + platform wiring) and
  `build-platform-only.mjs` — because **the wiring decides whether a `$type` bug
  exists at all**. Any native e2e must record which it used.
